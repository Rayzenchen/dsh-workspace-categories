# 工作区类别与分块高亮（@local/dsh-workspace-categories）

[English](README.en.md) | 中文

[![verify](https://github.com/Rayzenchen/dsh-workspace-categories/actions/workflows/verify.yml/badge.svg)](https://github.com/Rayzenchen/dsh-workspace-categories/actions/workflows/verify.yml)

侧边栏工作区一多、会话列表一展开，最容易出的事就是**看不清哪个会话属于哪个工作区**，更别说把「教学」「写作」「实验」这些不同用途的工作区分开。

这个插件给侧边栏加两层结构：

1. **每个工作区一块圆角卡片**——标题行和展开后的会话行都包在同一块里，上下内边距对称，相邻工作区不会糊成一片；
2. **始终置顶的类别块**——把工作区拖进带主题色的圆角容器里，容器里再套工作区卡片；类别可以收起、可以拖动排序、可以给每一类挑一个颜色。

## 安装

**要求**：DeepSeek Harness `0.2.3-alpha.2` 或更新（清单里的 `engines.dsh` 声明了这个范围，更老的版本会被拒绝）。纯 JavaScript，没有构建步骤，从 git 安装不需要额外的 `allowBuilds` 许可。

从 GitHub 安装（`v1.0.0` 是标签，也可以省略跟 `main`）：

```sh
dsh plugin --profile <profile> add github:Rayzenchen/dsh-workspace-categories#v1.0.0
```

从本地目录安装：

```sh
dsh plugin --profile <profile> add /path/to/dsh-workspace-categories
```

在 Desktop 应用里，也可以让 agent 用 `plugin_manager` 的 `install_bundle` 装同一个 spec。装完**刷新页面**即可（功能全在浏览器侧）；卸载用
`dsh plugin --profile <profile> remove @local/dsh-workspace-categories`。

## 用法

### 新建类别

点「工作区」标题右侧、**紧挨着「添加工作区」的那个按钮**（叠放卡片 + 加号）。点一下就地生成一个类别，名字直接进入编辑状态：打字、回车结束，Esc 取消。

不需要在添加工作区时先选类别——绝大多数工作区本来就不需要分类，需要时再拖进去。

### 归入 / 移出

把工作区行拖到类别色块上**任意位置**都算：标题、成员卡片、卡片的缝隙、空类别的虚线区。拖动时目标类别整块亮起，松手即归入；一个类别可以放任意多个工作区。

把类别里的工作区拖到下方「未分类」区域（分隔条、任意未分类工作区卡片、列表底部空白都行）就移出类别。

### 收起 / 展开

点类别标题的空白处，或标题左侧的小三角。收起后只剩一条标题，成员卡片隐藏但归属保留；把工作区拖进收起的类别会自动展开它，避免「拖进去了却看不见」。

### 排序

类别永远排在「未分类」之上，类别之间可以自由调序：

- 拖动标题左侧的六点把手；
- 或者直接拖动类别色块本身；
- 落点按**整个类别块的中线**判断：落在上半部分插到它前面，落在成员卡片区域就插到它后面，不会看起来像"塞进别人里面"；
- 拖到两个类别之间的缝隙时，取最近的那个作为插入点；
- 键盘：把手聚焦后按 `↑` / `↓`，或标题聚焦后按 `Alt+↑` / `Alt+↓`。

### 主题色

点类别名称前的**色点**，打开配色浮层：7 个 macOS 访达标签色（红、橙、黄、绿、蓝、紫、灰）。选完立即生效，面板保持打开方便对比；`Esc` 或点外面关闭。色块圆角、浮层材质与工作区行菜单一致。

### 重命名 / 删除

点类别最右侧的**三个点**，打开与工作区行右侧菜单同材质、同位置、同图标的浮层：

- `重命名`——也可以直接双击类别名称；
- `删除类别`——需要点两次确认；删除后成员工作区自动回到「未分类」，工作区本身和会话都不受影响。

### 键盘与无障碍

- 类别标题可获得焦点：`Enter` / `空格` 收起或展开，`Alt+↑` / `Alt+↓` 移动类别；
- 六点把手可获得焦点：`↑` / `↓` 移动类别；
- 「…」菜单支持 `↑` / `↓` / `Home` / `End` 在选项间移动，`Esc` 关闭并把焦点还给触发按钮，`Tab` 关闭菜单；
- 配色浮层的 7 个色块支持方向键移动与 `Enter` 选择；
- 每次新建、归入、移出、收起/展开、删除都会写入一个 `aria-live="polite"` 区域，屏幕阅读器能听到结果；
- 尊重 `prefers-reduced-motion`（关闭过渡与弹性动画）和 `forced-colors`（用真实描边代替半透明底色）。

## 视觉层次

| 层 | 外观 |
| --- | --- |
| 类别块 | 用户主题色低透明度铺底 + 同色细描边 + 16px 圆角；深色模式 alpha 更高、浅色更轻，两种外观层次一致。 |
| 类别标题 | 透明底（透出类别色）+ 左侧 2px 色条 + 色点 + 成员计数 + 底部细分隔线；收起时成为整块唯一的表面。 |
| 成员工作区卡 | 在 `bg-layer-1` 上混入 7%（浅色）/ 13%（深色）的类别主题色，带同色描边；12px 圆角，四边内缩 4px，类别色从卡片四周和卡片之间透出来。 |
| 未分类工作区卡 | 中性半透明卡片，16px 圆角，和类别块形成明显区别。 |
| 会话行 | 保持 DSH 原样，不加边框或底色。 |

文字始终使用 DSH 主题文字色，对比度不依赖类别颜色。两枚浮层直接用官方菜单材质（`--dsw-menu-surface-fill` + `--dsw-menu-backdrop-filter`）、官方圆角与阴影 token，深浅色下都与原生菜单一致。

## 数据与实现要点

- **存哪儿**：类别定义（名称、颜色、成员工作区 id、收起状态）是浏览器本地 UI 偏好，存在 `localStorage` 的 `dsh.workspace.categories.v1`，与 DSH 自己的侧边栏视图设置同类。插件不改工作区数据、不写会话记录、不联网；关掉插件后定义保留，重新启用会恢复。
- **为什么用 CSS `order`**：工作区行由 React 渲染，插件不搬动 React 拥有的节点，而是把列表变成纵向 flex 容器，只改每个工作区分组的 `order`，并插入自己的类别块/标题/浮层节点。归属只存工作区 id 集合，组内顺序继续由 DSH 的工作区顺序决定，所以原生拖动排序仍然有效。
- **类别块怎么"套住"卡片**：一个绝对定位的圆角背景层插在列表里（`z-index` 在卡片之下），高度按标题与可见成员卡片的实际位置量出；标题和成员卡片各自在它上面绘制，于是多块背景能叠出"容器里有卡片"的效果，而不需要移动 React 节点。布局分两阶段：先把所有节点顺序排完，再统一量背景块，避免量到半成品布局。
- **接缝不依赖哈希类名**：分组结构优先用 `data-slot` / `data-sidebar-*` / `data-row-key` / `role="tree"` 判断，CSS Modules 生成的类名只作为快路径；样式锚在自己写入的 `data-dsh-wsc-section` 等属性上。Harness 升级就算改了哈希类名，功能也不会静默消失。
- **热更新安全**：新实例启动时先让旧实例自己拆除（DOM、监听、观察器、定时器、样式、订阅），再清扫更早版本遗留的节点；旧实例的每个异步回调都检查"是否已销毁"。正常热更新不会叠出第二套类别框。
- **可观测面**：注册只读 Client 服务 `workspaceCategories`，`getSnapshot()` 返回类别定义、收起状态与布局模式。

## 兼容

- 与 [`@local/dsh-workspace-running-indicator`](https://github.com/Rayzenchen/dsh-workspace-running-indicator)（折叠工作区运行指示器）兼容：插件不删除、不替换工作区行，指示器插在名称前的转圈不受影响。
- 只在默认的 **「按工作区」分组视图** 里显示类别块。
- 「按工作区树」视图保留顶层工作区的分块高亮，但不显示类别；「单列表」视图没有工作区分组，插件不做任何装饰；侧边栏收成窄条、或进入会话搜索结果时，类别界面自动隐藏，退出后恢复。

## 已知限制

- 类别归属只存在当前浏览器（`localStorage`）。换浏览器、清理站点数据、或 Web 地址端口变化会丢失，不会同步到其他设备。
- 类别归属按工作区 id 记录；删除工作区后，它的归属会在下一次工作区快照到达时自动清理。工作区重命名不受影响。
- 类别块的位置依赖 DSH 侧边栏当前的 DOM 结构。结构大改时插件会退化成"不装饰"，并在控制台打一条一次性提示，不会报错或弄乱列表。
- 搜索视图、窄条（rail）里没有工作区行，因此没有类别界面。
- 归类操作以拖动为主；键盘可以收起、排序、重命名、删除，但把工作区归入类别目前仍需拖动。
- 自动视觉验证受限：本插件的自动化测试覆盖 DOM 行为（16 个场景、92 项断言），像素级外观仍需在应用里目视确认。

## 开发与验证

```sh
npm install      # 只有测试用的 jsdom
npm test         # 语法检查 + 92 项断言
```

`tools/verify-core.mjs` 用 jsdom 复刻真实侧边栏结构，加载**真实的** `client.js`，覆盖：注入按钮位置、新建/重命名/改色/收起/删除、拖入与拖出、指针与键盘排序、刷新后持久化、热更新接管、哈希类名变更后的结构回退、双语切换、屏幕阅读器播报、损坏存储的容错、工作区消失后的清理。CI 在每次推送时跑同一套检查。

## 版本历史

### 1.0.0

正式版：

- 工作区独立圆角分块；类别是带主题色的圆角容器块，深/浅色各一套强度，类别下卡片带淡淡主题色。
- 类别恒置顶、可收起、可拖动排序（把手 / 整块 / 键盘）、可自定义访达标签色。
- 新建按钮紧邻「添加工作区」；整块可接收拖放，一个类别容纳任意多个工作区；拖到「未分类」区域移出。
- 「…」菜单与工作区行菜单同材质、同位置、同官方图标（重命名 / 删除类别，二次确认）。
- 界面语言跟随应用，键盘可达，屏幕阅读器播报，尊重减少动效与强制色模式。
- 结构探测不再依赖 CSS Modules 哈希类名；热更新单一实例接管，不再需要重启清理。
- 附 jsdom 自检套件与 CI。
